# 24-05 Plan: 收紧 service 与 stream generation 所有权

## 目标

让异步启动、停止、退出和崩溃恢复只修改自己创建的 service/stream，迟到任务不得停止或覆盖新实例。

## 实施

1. Session event stream 启动返回 `stream_id`，前端 cleanup 只停止对应 id；若组件已卸载但启动随后才完成，立即回收该 id。
2. Tauri stream 使用单调 id 和 compare-and-swap active owner，旧 cleanup 不能清理新 stream。
3. Bot service 引入 generation；start、stop、app exit、monitor 和 delayed restart 在提交状态前校验 generation 与 pid。
4. 新启动进程若已被更新 generation 取代，立即终止，不写回共享状态。
5. service guard 显式读取 `AppExitState`，退出期间即使 autostart 条件仍成立也不再发起启动。

- `cargo test session_guard_only_auto_starts_when_enabled_and_service_is_stopped -- --test-threads=1` → `1 passed`

## 边界

- 不新增调度框架、锁服务、IPC schema 或依赖。
- 不改变正常 start/stop 的用户行为。
- 不执行 build、package、install 或 restart。
