# 24-07 Plan: 跨 owner 控制通道

## 归档处置

2026-09-05，用户同意将本计划移出 Phase 24 的完成范围，延期进入 [需求待办](../../REQUIREMENTS.md#deferred-backlog)。本计划未完成，技术阻塞与下列验收条件保留；不再阻塞 Phase 24 归档。范围决定见 [24-ARCHIVE.md](24-ARCHIVE.md)。

## 目标

当目标 session 正由 Codex Desktop、CLI 或其他 app-server owner 执行时，OnlineWorker 连接该 owner 的既有控制通道：普通 TG 消息走官方 steer/queue，TG 中断调用同一 owner 的真实 interrupt，commentary/final 返回原 Topic。

## 当前已完成的诚实降级

- `codex queue` 成功后返回 `status=queued`，TG 明确显示“已排队，当前任务结束后处理”，不再记录为已发送。
- active-writer interrupt 失败会明确提示“普通消息只能排队，无法立即中断”，并且不会把中断降级成普通文本 queue。
- rollout commentary 仍通过 Phase 24 source claim 返回原 TG placeholder。
- 定向 `4 passed`，相关 Codex 三文件回归 `105 passed, 1 skipped`。

## 原阻塞证据

本机 Codex CLI `0.150.1` 暴露 `codex queue --thread`，但没有 interrupt 子命令。当前 Codex Desktop session 的 rollout metadata 与 `state_5.sqlite.threads` 均不记录 owner endpoint；默认 `~/.codex/app-server-control/app-server-control.sock` 连接被拒绝。Desktop 的 `~/.codex/ipc/ipc.sock` 是 App 私有 IPC，仓库没有稳定协议或可复用客户端。OnlineWorker 自有 `onlineworker-app-server.sock` 不是 Desktop 当前 turn 的 owner，不能绕过 single-writer 锁冒充控制端。

因此，现有公开能力只能可靠 queue，不能发现 Desktop owner 并对其执行真实 `turn/interrupt`。在没有 owner endpoint/控制 API 前，本计划不能声称完成。

## 2026-09-26 复核

- 本机 CLI 已为 `0.157.1`。`codex app-server daemon version` 在允许访问本地 socket 后仍返回 `Connection refused`，默认公开控制通道不可达。
- 该版本导出的 experimental JSON Schema 支持 `thread/loaded/list`、`thread/read`、`thread/resume`、`turn/steer` 和 `turn/interrupt`，未发现 session → owner endpoint 的专用查询方法或 `Thread` 字段。[官方协议文档](https://learn.chatgpt.com/docs/app-server) 确认已有 endpoint 上可执行 steer/interrupt；这不证明可以发现或接管独立 Desktop owner。
- 仓库已有 managed app-server、remote proxy 和常驻 adapter；CLI attach 同一 upstream 的路径可复用。`resolve_connection_target` 只使用已配置的 URL/端口，或启动自有实例，不负责发现独立 Desktop owner。继续增加同类控制层不能解除当前阻塞。
- 现有回归分别覆盖 steer、queue、interrupt 失败不入队、source claim 与消息流；尚无真实 Desktop active-writer 的三段闭环验收。本次仅核验公开接口、连接可达性和代码路径，未运行真实输入/中断/TG 发送，未改变运行时配置。

结论：保留 `deferred`。托管路径可继续补集成验证；原定独立 owner 场景仍需满足下列解阻条件，不能以 mock 或第二 writer 的结果代替验收。

## 解阻条件

满足任一项后继续：

1. Codex 提供可发现的 session → owner app-server endpoint，并允许 `turn/interrupt`；或
2. 目标 session 从创建时即通过 OnlineWorker remote proxy/managed app-server 托管，使 OnlineWorker 持有原始控制连接。

## 验收

1. 不启动第二 writer；能够识别并连接当前 owner。
2. TG 普通消息在源 session 中可观察，并明确返回 sent/queued disposition。
3. TG interrupt 改变当前 turn 状态，且从不降级为普通 queue 文本。
4. owner commentary/final 回到原 TG Topic，exactly-one。
5. 使用真实 active-writer session 完成输入、interrupt、输出回流三段验证。

## 范围

- 不逆向或依赖 Codex Desktop 私有 `ipc.sock`。
- 不新增第三套镜像/轮询链，不破坏 single-writer 锁。
- 未解阻前不 build、package、install 或 restart。
