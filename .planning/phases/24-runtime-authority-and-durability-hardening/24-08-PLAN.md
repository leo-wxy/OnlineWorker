# 24-08 Plan: 最小稳定性收口

## 目标

修复源码审计确认的三个仓库内缺口：本地 owner 发送失败被误记为 accepted、provider overlay 未读取已有备份且损坏结构会被清空写回、service 旧 generation 的延迟重启守卫缺少直接回归。

## 实施

1. 复用 `handle_local_owner` 现有返回值形成三态合同：`False` 表示未接管，`True` 表示已接管且接受，`None` 表示已接管但发送失败；失败不再发布 `message.user.accepted`，也不继续第二条发送链。
2. provider overlay 读取主文件失败或结构无效时尝试现有 `.bak`；本地归档写入遇到非 object 的 `workspaces/workspace/threads/thread` 时返回错误，保留原文件。
3. 抽出 service 延迟重启的现有布尔条件，并用最小单测固定旧 generation/PID 不能清理或重启新实例。

## 验证

- Python：本地 owner 成功、未接管、失败三态回归。
- Rust：overlay 主文件损坏后的备份恢复、损坏嵌套结构不写回、旧 generation 延迟重启守卫。
- `cargo fmt --all -- --check`、Python compile、`git diff --check`。

## 边界

- 不增加新类型、框架、依赖、跨语言锁或公开 schema。
- `onlineworker_state.json` 的跨进程单 writer 重构另立后续切片；本计划只阻止已确认的损坏写回并复用现有备份。
- `24-07` 继续保持 blocked；不逆向 Codex Desktop 私有 IPC。
- 不执行 build、package、install、restart、commit 或 push。
