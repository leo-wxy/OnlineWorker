# 25-03: 新建会话的分阶段恢复

依赖 25-01、25-02。复用 AppStorage、ThreadInfo、MessageEventBus 与原有 provider 边界。

- [x] provider 创建成功后尽早保存真实 thread ID 与原始 source，保留首消息与绑定步骤的恢复状态。
- [x] topic 失败仅影响 IM 绑定，真实会话与总线消息保留；重试只补做未完成步骤。
- [x] 发送成功但保存失败保留“已发送、待恢复”的事实，不引导重新创建或重复发送。
- [x] 发送结果不确定时禁止自动重试；不将源端会话自动删除或归档作为失败补偿。
- [x] App 首消息与 Telegram /new 复用同一恢复语义，失败信息与恢复状态经总线显示。

源码验证：新建、请求重用、并发创建、topic 失败、首消息不确定、发送后保存失败、磁盘恢复记录及恢复后的投影状态均有聚焦覆盖。安装版验证尚未执行；本轮未向外部 IM 发送测试消息。
