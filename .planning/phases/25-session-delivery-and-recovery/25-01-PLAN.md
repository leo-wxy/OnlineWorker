# 25-01: 发送边界、会话失效与状态写入权威

按用户批准的顺序修复重复执行、旧事件串入和状态覆盖；复用现有 owner bridge、MessageEventBus 与 AppStorage。

- [x] 发送只在请求写入前等待连接；写入后结果不确定及业务拒绝不自动重试。
- [x] 归档不在结果不确定后换入口再次执行；App 与 Telegram 归档由 Python AppStorage 保存并发布总线事件，Rust 不直接覆盖主状态文件。
- [x] Channel cleanup 后拒绝事件；聊天身份包含 provider/session/workspace；归档、发送与附件的迟到结果不能更新新选择。
- [x] 配置读改写共用写锁，全文编辑保存校验 revision，拒绝陈旧全文覆盖。
- [x] 排队、接受和发送失败语义明确，失败事件经总线发布且不伪造 provider turn 失败。

验证：真实临时 Unix socket 的响应丢失/拒绝测试；迟到事件与异步回调测试；临时状态、配置文件的归档覆盖/并发写入测试；相关 Python/Rust/Node 回归与 TypeScript 检查。

离线归档第一版要求服务恢复后重试，不引入离线 journal。所有测试使用合成 session 和临时目录，不操作用户历史。

源码检查与快速安装版回归已通过：重启后已有无 topic 运行中会话恢复，新回复自动进入任务页，无需刷新。
